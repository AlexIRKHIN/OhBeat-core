# ADR 0008. MinIO собирается из исходников

Дата: 31.10.2026. Статус: принято (вынужденное решение при запуске среза 0).

## Контекст

CLAUDE.md задаёт MinIO как замену S3 в локальной среде. При первом запуске выяснилось, что открытый MinIO с 2025 года заархивирован:

- `dl.min.io` на любой бинарник отвечает `410 Gone`;
- образов `minio/minio` и `minio/mc` больше нет на Docker Hub, а на quay.io они требуют авторизации.

Исходный код на GitHub (`github.com/minio/minio`) по-прежнему доступен.

## Варианты

- **Собрать MinIO из исходников.** Архитектура, документация и CLAUDE.md не меняются. Минусы: первая сборка идёт несколько минут; архивная версия не получает обновлений безопасности.
- **Перейти на другое S3-совместимое хранилище** (SeaweedFS, Garage, RustFS). Оно поддерживается, но требует проверки совместимости: presigned POST с `content-length-range`, lifecycle, политики анонимного чтения, Range-запросы. И это отступление от CLAUDE.md.

## Решение

- `infra/minio/Dockerfile` собирает MinIO `RELEASE.2025-04-22T22-12-26Z` из официального репозитория (multi-stage сборка в `golang:1.24-alpine`). Это последний релиз с полной веб-консолью.
- Утилита `mc` больше не нужна: бакеты, анонимное чтение `public-media` и lifecycle 24 ч на `temp-uploads` настраивает скрипт `backend/seeds/init_storage.py` через обычный S3 API (сервис `storage-init` в `docker compose`).

## Последствия

- Отсутствие обновлений безопасности допустимо: среда только локальная, боевого запуска не планируется.
- Код работает с хранилищем через интерфейс `ObjectStorage`, поэтому замена MinIO на другое S3-совместимое хранилище затронет только окружение.
