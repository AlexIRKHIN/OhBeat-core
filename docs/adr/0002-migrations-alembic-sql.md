# ADR 0002. Миграции: Alembic с миграциями на чистом SQL

Дата: 31.10.2026. Статус: принято.

## Контекст

Первая миграция должна давать ровно схему из `05_Database/schema.sql`, включая `CHECK`, индексы и права роли `ohbeat_app`.

## Варианты

- **Alembic с SQL-файлами.** Тот же Python, что и в бэкенде; тесты сами поднимают чистую БД. Минус: каждый SQL-файл обёрнут в маленький Python-файл.
- **dbmate.** Миграции — чистые `.sql`-файлы, но это отдельная утилита на Go, и тестам сложнее управлять схемой.

## Решение

Alembic. Тело каждой миграции — отдельный `.sql`-файл, Python-файл ревизии только выполняет его. Автогенерация схемы из моделей не используется. Миграция `0001` выполняет копию `schema.sql` из документации без изменений, плюс `GRANT`/`REVOKE` из её шапки.

## Последствия

- Совпадение с эталоном проверяется тестом: БД, созданная напрямую из `schema.sql`, и БД после миграции `0001` дают одинаковый `pg_dump --schema-only`.
- Миграции применяет отдельный пользователь-владелец схемы, приложение работает под ролью `ohbeat_app` (GAP-5).
