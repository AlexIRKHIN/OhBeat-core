# ADR 0007. Дополнения к schema.sql — отдельной второй миграцией

Дата: 31.10.2026. Статус: принято (решение аналитика).

## Контекст

В 21 таблице `schema.sql` нет хранилища для ротации и отзыва refresh-токенов и для лимита неудачных входов (GAP-1). Нет `UNIQUE` на `contracts.order_item_id`, хотя логическая модель допускает не больше одного договора на позицию (GAP-2). Нет индексов под фильтры каталога и внешние ключи (GAP-3).

## Варианты

- **Вторая миграция.** Первая даёт ровно `schema.sql`, вторая добавляет недостающее. Структура 21 таблицы не меняется.
- **Строго 21 таблица.** Отозванные токены и счётчик входов держать в памяти процесса (теряются при перезапуске), уникальность договора — только в коде.

## Решение

Миграция `0002` добавляет:

- таблицу `refresh_tokens` (хэш токена, семейство, пользователь, срок, `revoked_at`);
- таблицу `login_attempts` (email, время, успех);
- `UNIQUE (order_item_id)` на `contracts`;
- индексы для каталога, внешних ключей и фильтров Audit Log.

Права на новые таблицы выдаются роли `ohbeat_app` той же миграцией.

## Последствия

- Каждое дополнение помечено в коде миграции ссылкой на свой GAP.
- Тест на совпадение с эталоном сравнивает именно состояние после `0001`.
