# Срез 2. Каталог, стриминг превью и страница продюсера — план

Статус: **ждёт «ок» аналитика**. Общий план — [PLAN.md](../PLAN.md). Источники: REST API §2.3, §2.9, §2.10; `RFC_Audio_Streaming.md`; US-A1, US-A2, US-P5; UC-1…UC-3.

## 1. Что получится

Любой посетитель, даже без входа, открывает каталог на главной странице, фильтрует биты по жанру, BPM, тональности и цене и листает дальше кнопкой «Показать ещё». Превью играет в одном общем плеере внизу экрана: с перемоткой и без скачивания трека целиком, а при переключении на другой бит прежнее скачивание обрывается. У каждого бита своя страница: описание, лицензии с ценами и составом файлов. У продюсера — публичная страница с витриной его битов.

## 2. Требования

| Требование | Что делаем |
| --- | --- |
| US-A1, UC-3, RFC стриминга | Один плеер: `preload="none"`, перемотка Range-запросами, обрыв скачивания при переключении (`pause()` → `removeAttribute('src')` → `load()`) |
| US-A2, UC-1, UC-2 | Каталог с фильтрами `genre`, `bpm_min`, `bpm_max`, `musical_key`, `price_max`, сортировка `newest`, курсорная пагинация |
| FR-19 | Бит в резерве виден в каталоге с меткой «В резерве» (`is_reserved: true`) |
| FR-24 (часть) | Проданные Exclusive (`sold`) в каталог не попадают |
| FR-15 (часть) | В каталоге и на странице бита — цены Продюсера, без комиссии сервиса |
| FR-34 (перенесено из среза 1), US-P5 | Публичная страница продюсера с витриной (`GET /producers/{id}`) |
| NFR-1 | Каталог отвечает быстро: запрос опирается на индекс из миграции 0002 (`published_at DESC, id DESC` по `active` и `reserved`) |
| NFR-9, NFR-21 | Сетка карточек от 320 px до десктопа |
| NFR-27, NFR-28 | Цены «1 500 ₽», даты ДД.ММ.ГГГГ |

## 3. Новые термины

- **HTTP Range-запрос** — браузер просит не весь файл, а кусок: «дай байты с 1 472 000 до конца». Сервер отвечает `206 Partial Content` и присылает только этот кусок. Так работает перемотка: плеер считает по длительности, с какого байта начинается нужная секунда, и запрашивает этот кусок.
- **Курсорная пагинация** — следующая страница запрашивается не по номеру («страница 3»), а «после вот этого бита». Курсор — закодированная метка последнего показанного бита. Если пока вы листаете появится новый бит, страницы не съедут, и один бит не покажется дважды.
- **Ключ сортировки (keyset)** — сортируем по паре «дата публикации, id». Следующая страница — это «всё, что старше последнего показанного». Такой запрос быстро работает по индексу, сколько бы битов ни было.
- **Глобальный плеер** — один элемент `<audio>` на всё приложение. Кнопки Play в карточках им управляют, а не создают свои плееры. Поэтому две песни одновременно не заиграют, а прежнее скачивание обрывается.

## 4. Как пройдут запросы

**Каталог.** Браузер → `GET /v1/beats?genre=Trap&bpm_min=80&price_max=2000` → Core API строит один SQL-запрос:

```
SELECT … FROM beats
WHERE status IN ('active','reserved')
  AND (жанр: EXISTS в beat_genres)
  AND bpm BETWEEN … AND musical_key = …
  AND (price_max: EXISTS активная лицензия с ценой ≤ price_max)  -- то же самое, что «минимальная цена ≤ price_max»
  AND (published_at, id) < (курсор)                              -- следующая страница
ORDER BY published_at DESC, id DESC
LIMIT 21                                                         -- 20 + 1, чтобы понять, есть ли ещё
```

Ответ — карточки (§2.3) и `next_cursor`. Ссылки на обложку и превью ведут прямо в публичный бакет MinIO: он играет роль CDN.

**Превью** (RFC §3): нажатие Play → плеер ставит `src` = ссылка на превью → браузер сам запрашивает `Range: bytes=0-` у MinIO → `206` → звук. Перемотка → новый `Range: bytes=N-` → `206`. Core API в этом не участвует совсем.

**Страница продюсера.** `GET /v1/producers/{id}` → профиль и первая страница его битов с теми же фильтрами. Следующие страницы — `?cursor=…`.

## 5. Эндпоинты

| Метод и путь | Доступ | Ответы |

## 6. Экраны

- **Каталог** (главная страница):
  - панель фильтров: жанр, BPM от–до, тональность, максимальная цена; кнопка «Сбросить»;
  - фильтры записываются в адрес страницы, поэтому ссылкой с фильтром можно поделиться;
  - карточки: обложка, кнопка Play, название, ссылка на продюсера, жанры, BPM и тональность, длительность, цена «от 1 500 ₽», метка «В резерве»;
  - «Показать ещё»;
  - все состояния: загрузка, «Ничего не найдено» с кнопкой сброса фильтров, ошибка с «Повторить», нет связи.
- **Страница бита:** обложка, плеер, описание, жанры, BPM, тональность, длительность, таблица лицензий — цена и что входит (MP3 / WAV / стемы / исключительные права). Кнопка покупки появится в срезе 3, пока таблица только информационная.
- **Страница продюсера:** аватар, имя, описание и витрина битов с теми же фильтрами.
- **Плеер внизу экрана** (на всех страницах): обложка, название, Play/Pause, шкала перемотки, время. В «Моих битах» вместо отдельных плееров тоже кнопка Play.

## 7. Тесты

**Core API:**
- каждый фильтр отдельно и вместе;
- `price_max` смотрит на *минимальную активную* цену: выключенная дешёвая лицензия не учитывается;
- в выдаче только `active` и `reserved`: `uploading`, `processing`, `rejected`, `hidden`, `sold`, `deleted` не видны; у `reserved` — `is_reserved: true`;
- порядок «сначала новые»;
- курсор стабилен: новый бит, опубликованный между первой и второй страницей, не вызывает ни дублей, ни пропусков;
- `limit` в границах;
- неверные параметры → `400`: BPM вне 40–300, `bpm_min > bpm_max`, неизвестная тональность, битый курсор;
- страница продюсера: профиль, только его биты, фильтры, `404` для пользователя без роли Продюсера.

**Стриминг:** превью в публичном бакете отвечает `206` с `Content-Range` на `Range`-запрос (через Core API это не проходит, проверяем MinIO напрямую).

**Фронтенд:**
- плеер при переключении трека вызывает `pause()`, `removeAttribute('src')`, `load()` (RFC §4), а до нажатия Play не задаёт `src`;
- фильтры ↔ адрес страницы;
- формат цены «1 500 ₽».

## 8. Как вы сможете проверить и посмотреть своими глазами

1. Для наглядности — **демо-набор битов**: скрипт публикует 12 битов с разными жанрами, BPM, тональностями и ценами через настоящий путь (API → MinIO → Worker). Иначе фильтры и «Показать ещё» не на чем проверять: в каталоге сейчас 2 бита. Скрипт лежит в репозитории, запуск — одной командой.
2. Откройте главную без входа → поиграйте фильтрами → «Показать ещё».
3. DevTools → Network → фильтр «Media»:
   - до нажатия Play запросов к MP3 нет;
   - после Play — ответ `206`;
   - при перемотке в ещё не скачанное место — новый `206` с другим `Range`;
   - при переключении на другой бит прежний запрос становится «(canceled)».
4. Задержка старта звука (метрика RFC §6) выводится в консоль браузера: «first sound in N ms».
5. Страница бита и страница продюсера, ширина 320 px.

## 10. Оценка

Сложность **M**. Один проход без деления на части: Core API → плеер и экраны → демо-набор → проверка в браузере → отчёт.
