# Финал. Сквозная проверка, запуск с нуля, README

Дата: 12.11.2026. Что требовалось (CLAUDE.md, «Порядок работы», п. 5): сквозная проверка всего пути, инструкция по запуску с нуля одной командой и README с описанием продукта.

## Что сделано

- **Сквозной автотест** `frontend/e2e/full-path.spec.ts` на Playwright, в Chromium и WebKit (Safari, NFR-15). Запуск: `docker compose --profile e2e run --rm e2e`. Тест проходит весь путь только через интерфейс:
  1. регистрация Продюсера с согласиями → данные для договора → подключение к продажам;
  2. загрузка бита: обложка, WAV и ZIP со стемами генерируются тестом в памяти и уходят прямо в MinIO → Media Worker → «Опубликован»;
  3. регистрация Артиста → страница бита в каталоге, цена без комиссии;
  4. Basic: корзина → оферта → оплата на странице мока ЮKassa → «Оплата прошла: 1 650 ₽» → MP3 и PDF-договор по ссылкам → хэш скачанного PDF совпадает с `SHA-256` в «Моих покупках» → Продюсеру ушло письмо о продаже;
  5. Exclusive: резерв → кнопка оплаты выключена → текст договора → код из SMS (сначала неверный: «осталось попыток: 2») → подпись → оплата 22 000 ₽ → MP3, WAV, стемы, договор → бит исчез из каталога.
- **Как тест видит «наружу»:**
  - В контейнере теста порты 5173, 9000 и 8100 перенаправлены на сервисы docker-сети байт в байт. Браузер теста ходит на те же адреса, что и ваш, поэтому подписи presigned-ссылок остаются верными.
  - Мок SMS и email кроме лога пишет «входящие» в файл на общем томе (`MOCK_INBOX_PATH`). Тест берёт код оттуда, как человек — из SMS.
- **Запуск с нуля одной командой:** `docker compose up --build`.
  - `.env` больше не обязателен: значения по умолчанию берутся из `.env.example`, а `.env` перекрывает нужные строки.
  - Новый одноразовый сервис `demo-seed` сам публикует демо-каталог через настоящий путь и завершается. Повторный запуск ничего не дублирует.
- **README** — что это за продукт, запуск, адреса консолей, демо-аккаунты, сценарии ручной проверки, тесты, устройство, ссылки на ADR, GAP и отчёты.

## Ошибка, которую нашёл сквозной тест

В форме загрузки бита ошибка цены «От 100 до 500 000 ₽» появлялась сразу при включении лицензии и **оставалась, пока поле не потеряет фокус**, даже если цена уже введена правильно. Первый клик куда угодно убирал эту строку, блок лицензий сдвигался вверх, и клик промахивался: в WebKit не ставилась галочка Exclusive, в Chromium не нажималась «Опубликовать бит». Человек в Safari столкнулся бы с тем же. Исправлено: пока у цены есть ошибка, поле проверяется на каждый ввод, и строка исчезает сразу, как только цена стала правильной (коммит `fix(NFR-11)`).

## Как проверить руками

```bash
docker compose up --build
```

Затем откройте <http://localhost:5173>, демо-аккаунты — в `.env.example` (`SEED_*`). Сценарии — в README, раздел «Сценарии для ручной проверки».

Сквозной тест:

```bash
docker compose --profile e2e run --rm e2e
```

Отчёт с трассировкой каждого шага: `frontend/playwright-report/index.html`.

## Что важно знать

- **Данные сквозного теста** попадают в то окружение, где он запущен: новые пользователи `producer-…@example.com` и `artist-…@example.com`, биты «E2E …». Каждый прогон создаёт своих пользователей, поэтому прогоны не мешают друг другу.
- **Первый прогон дольше:** скачивается образ Playwright с браузерами (около 2 ГБ).
- **Проверочный стенд «с нуля»** работал под именем проекта `ohbeatfresh`. Его контейнеры удалены, а тома `ohbeatfresh_*` оставлены: удалять их — решение аналитика.
